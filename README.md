# DESYNCER

**Байт-точный пробер HTTP request smuggling / desync на сырых сокетах.** C++17, POSIX, ноль внешних зависимостей.

DESYNCER отправляет HTTP/1.1-запросы **ровно так, как заданы** — два `Content-Length`, обфусцированный `Transfer-Encoding`, голый `LF` без `CR`, пробел перед двоеточием. Это те самые байты, которые `curl`, `requests`, `net-http` и Burp-репитер молча «нормализуют» и потому не могут воспроизвести. Расхождение front-end / back-end в разборе длины тела детектируется **неразрушающим тайминг-оракулом** на монотонных часах.

> ⚠️ **Только для авторизованного тестирования.** Отправляйте трафик исключительно на системы, которые вы имеете право проверять: свои, в scope bug-bounty с явным разрешением, по договору на пентест. Отправка таких запросов на чужую инфраструктуру может быть незаконной и вредоносной. Ответственность на вас.

## Почему C++

Инструменту нужен полный контроль над байтами на проводе: сегментацией TCP (`TCP_NODELAY`), моментом `write()`, монотонными часами для тайминга и отсутствием любой нормализации заголовков. Ни один HTTP-клиент высокого уровня этого не даёт — он «чинит» ваш пейлоад раньше, чем тот уйдёт в сеть.

## Сборка

```sh
make            # → ./desyncer
make run-dry    # показать пробы, ничего не отправляя
make clean
```

Нужен только компилятор C++17 (`clang++`/`g++`) и POSIX-окружение (Linux, macOS, *BSD).

## Использование

```sh
desyncer <target> --scope <file> --i-am-authorized <host> [опции]
```

Цель: `host`, `host:port` или `http://host[:port]/path`.

Без `--scope` **и** `--i-am-authorized` инструмент работает только в **dry-run**: печатает запросы, но ничего не отправляет.

### Пример

```sh
# 1. Посмотреть, что вообще будет отправлено (безопасно, оффлайн):
desyncer http://target.example/api --dry-run

# 2. Реальный прогон по авторизованной цели:
echo "target.example" > scope.txt
desyncer http://target.example/api \
    --scope scope.txt \
    --i-am-authorized target.example \
    --repeats 7 --timeout 5000 --out poc.txt
```

## Как работает детектор

Классические тайминг-пробы (по методике James Kettle):

- **CL.TE** — front-end доверяет `Content-Length`, back-end — `Transfer-Encoding`. Пейлоад сделан так, что back-end (TE) после первого чанка ждёт продолжения, которое front-end (CL) уже не пришлёт → соединение **висит**. Задержка ⇒ вероятен CL.TE.
- **TE.CL** — наоборот: front-end (TE) завершает по нулевому чанку, back-end (CL) ждёт больше байт, чем пришло → **висит**. Задержка ⇒ вероятен TE.CL.

Каждая проба измеряется **N раз** на свежих соединениях; берутся медиана и σ времени до первого байта (TTFB). Проба помечается `ВИСИТ`, если её медиана значимо (в σ и в абсолюте) выше базовой линии или большинство прогонов ушло в таймаут. Медиана + σ вместо оценки «на глаз» отсекают джиттер сети.

Каталог включает обфускации `Transfer-Encoding`: пробел перед двоеточием, таб, вертикальный таб, отсутствие пробела, obs-fold (перенос строки), дублирование, а также разделители строк голым `LF`.

## Этика: authorized-only by design

Три слоя гейта, **fail-closed**:

1. **Scope-allowlist** (`--scope`) — отправка запрещена, если хост не входит в allowlist (сравнение по суффиксу домена).
2. **Явное подтверждение** (`--i-am-authorized <host>`) на каждый хост, иначе только dry-run.
3. **Safe-mode по умолчанию** — тайминг-пробы идут на **отдельном** соединении и лишь измеряют его задержку. Инструмент **не** инжектирует отравляющий префикс в чужой keep-alive и не травит кэш, то есть не задевает других пользователей цели.

Тайминг-оракул даёт **кандидатов**, а не подтверждение. Верифицируйте вручную по сохранённым сырым req/resp прежде, чем включать находку в отчёт.

## Ограничения MVP

- Только `http://` (без TLS). Поддержка HTTPS через опциональный OpenSSL — на дорожной карте.
- Однопоточный; пул соединений — на дорожной карте.
- Тайминг-детектор чувствителен к нестабильной сети — поднимайте `--repeats` и `--sigma` на «шумных» целях.
